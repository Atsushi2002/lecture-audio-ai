## 4. 次にやること

1. 自分のGemini APIキーを取得（https://aistudio.google.com/apikey）
2. `index.html` をローカルで開き、**「接続テスト」** を押して疎通を確認
3. 30秒程度の mp3 を用意して実行 → 文字起こしと要約が出るか確認
4. GitHubに push → Settings → Pages で公開
5. スマホでアクセスして `docs/TESTCASES.md` の TC-01〜08 を実施、スクショを `screenshots/` に保存
6. `docs/TESTCASES.md` の結果欄を埋める
7. このファイルの URL 欄と「詰まった点」を更新して提出

## 5. 詰まった点と対処（随時追記）

### 設計段階で先回りして潰したもの

| 想定される詰まり | 対処 |
|---|---|
| AIが `gemini-1.5-flash` など古いモデル名を出してくる | 公式Models一覧を先に調査し、`API_NOTES.md` に「使ってはいけない名前」を明記。UIのプルダウンも公式一覧の名前だけにした |
| 認証方式の間違い（Bearer / `?key=`） | 公式RESTサンプルどおり `x-goog-api-key` ヘッダを採用 |
| `.m4a` を選んで400になる | 公式の対応形式リストに m4a が無い。拡張子チェックで選択時に警告し、変換を案内 |
| 20MB制限に引っかかる | base64で約1.33倍になることを考慮し、元ファイル15MBでガード。APIを叩く前に止める |
| どこで失敗したか分からない | 文字起こしと要約を別リクエストに分離。さらに「接続テスト」ボタンでテキストのみの疎通を単独で確認できるようにした |
| `parts` が複数返って本文が欠ける | `parts[*].text` を全部連結する実装にした |
| 要約が ```json で囲まれて返る | 寛容なパーサ（コードフェンス除去＋`{}`抽出＋箇条書きフォールバック）を実装 |
