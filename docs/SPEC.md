# SPEC.md — 講義音声ノートAI（Gemini API連携）

作成日: 2026-08-04 / 対象: 研修課題5（DAY5）

## 1. 目的

大学の講義・自習の録音を投入すると、**文字起こし / 要約（3行）/ 要点（3〜5個）** を自動生成して画面に表示する、スマホ対応のWebアプリを作る。

本当の狙いは「コードが書けるようになること」ではなく、**仕様 → 実装 → 検証 → ナレッジ化** のループを回せるようになること。

## 2. スコープ

### やること（MVP）

- 講義名の入力（任意）
- 音声ファイルのアップロード（ファイル選択のみ）
- Gemini API による文字起こし
- 文字起こしを元にした要約・要点の生成
- それぞれのコピーボタン
- APIキーの端末内保存（localStorage）
- スマホで崩れないレスポンシブUI

### やらないこと（今回は切り落とす）

- ブラウザ録音（MediaRecorder）
- サーバー / DB / 認証
- Google Drive 保存、LINE共有
- 履歴機能

**理由:** 課題の主眼は「外部API連携を自力で通すこと」。周辺機能を足すと沼りやすく、MVPが出ない。まず動くものを出してから拡張する。

## 3. 画面の流れ（ユーザー導線）

```
[初回] APIキー入力 → 保存（localStorage）
   ↓
[1] 講義名を入力（任意・推奨）
   ↓
[2] 音声ファイルを選択（wav / mp3 / aac / ogg / flac / aiff）
   ↓
[3]「文字起こし＆要約を実行」ボタンを押す
   ↓
[4] 進捗表示（① 文字起こし中 → ② 要約中）
   ↓
[5] 文字起こし（全文）を表示 ＋ コピーボタン
[6] 要約（3行）＋ 要点（3〜5個）を表示 ＋ コピーボタン
```

タップ対象は最小44pxを確保し、1カラムで縦に積む。

## 4. 入力

| 項目 | 必須 | 内容 |
|---|---|---|
| APIキー | 必須 | Google AI Studio で取得。localStorage に保存。画面ではマスク表示 |
| 講義名 | 任意 | 例「情報理論 第5回」。要約プロンプトの文脈に使う |
| 音声ファイル | 必須 | 公式サポート形式のみ。推奨は 30秒〜2分の短いサンプル |

## 5. 出力

| 出力 | 内容 |
|---|---|
| 文字起こし | 全文をそのまま表示（編集不要）。コピー可 |
| 要約 | 3行程度の文章。コピー可 |
| 要点 | 箇条書き 3〜5個。要約と一緒にコピー可 |

## 6. 処理フロー（2段階に分ける）

課題ガイドの「詰まりにくい順番」に従い、**文字起こし** と **要約** を別リクエストに分ける。
片方が失敗したときにどちらが原因か切り分けやすいため。

1. **STEP1: 文字起こし**
   音声ファイル → base64 → `inlineData` として `generateContent` に送信 → テキスト取得
2. **STEP2: 要約**
   STEP1の結果テキスト（＋講義名）→ `generateContent` に送信 → JSON `{summary, points[]}` を取得

さらに、切り分け用に **「テキストだけでAPI疎通確認」ボタン**（接続テスト）を用意する。
公式トラブルシュートの「まずテキストだけでGemini APIが呼べるか確認」に対応。

## 7. エラー時の表示

| 状況 | 画面表示 |
|---|---|
| APIキー未入力 | 「APIキーを入力してください」＋ キー入力欄にフォーカス |
| ファイル未選択 | 「音声ファイルを選択してください」 |
| 非対応形式 | 「この形式は対応していません。wav / mp3 / aac / ogg / flac / aiff を選んでください」 |
| ファイルが大きい（目安15MB超） | 「ファイルが大きすぎます（inline送信は合計20MBまで）。短く切って試してください」 |
| HTTP 400 | 「リクエスト形式かモデル名が誤っている可能性があります」＋ レスポンス本文を折りたたみ表示 |
| HTTP 401 / 403 | 「APIキーが無効か、権限がありません。キーの前後の空白も確認してください」 |
| HTTP 429 | 「レート上限です。少し待ってから再実行してください」 |
| HTTP 5xx / 通信失敗 | 「サーバー側または通信のエラーです。再試行してください」 |
| 空レスポンス | 「AIから本文が返りませんでした。音声が無音／短すぎる可能性があります」 |

エラーは **必ずレスポンス全文を画面にテキストで出す**（AIに相談するとき貼れるように）。

## 8. API仕様（詳細は docs/API_NOTES.md）

- エンドポイント: `POST https://generativelanguage.googleapis.com/v1beta/models/{MODEL}:generateContent`
- 認証: HTTPヘッダ `x-goog-api-key: <APIキー>`
- モデル名は **公式Models一覧に載っているものだけ** を使う（`gemini-1.5-*` のような古い名前を使わない）
- 既定モデル: `gemini-3.5-flash`（画面のプルダウンで変更可）
- 音声はリクエストに `inlineData`（base64）で同梱。合計リクエストは20MBまで
- 根拠URL: https://ai.google.dev/gemini-api/docs/audio , https://ai.google.dev/gemini-api/docs/models

## 9. セキュリティ / 取り扱い

- **APIキーをコードに直書きしない。リポジトリに含めない。** 入力値は localStorage のみに保存
- `.gitignore` に `.env` 系と `screenshots/*private*` を記載
- 個人情報・機密を含む音声はアップロードしない（講義の短いサンプルで検証）
- スクリーンショットにキーや個人情報を写さない（キー欄は `password` type でマスク）
- 本アプリはフロントエンドから直接APIを叩くため、**キーはブラウザに露出する**。自分専用のローカル/個人利用が前提で、他人に配る用途には使わない（その場合はサーバー経由に変更が必要）
