# はじめてのGitHub公開ガイド（コマンド不要）

プログラム経験ゼロ・GitHub初めての人向けに、**マウス操作だけ**でアプリを公開する手順です。
ターミナル（黒い画面）は一切使いません。

所要時間: 30分程度（初回）

---

## 全体の流れ

```
① リポジトリを作る
② ファイルをアップロードする      ← ドラッグ&ドロップ
③ GitHub Pages で公開する         ← 設定を3クリック
④ APIキーを入れて動作確認
⑤ スクリーンショットを撮る
⑥ 提出する
```

---

## 用語（3つだけ覚えれば十分）

| 言葉 | 意味 |
|---|---|
| **リポジトリ（repository）** | ファイルの置き場所。フォルダだと思ってOK |
| **コミット（commit）** | 「保存」ボタン。変更を記録すること |
| **GitHub Pages** | 置いたファイルをWebサイトとして公開してくれる無料機能 |

---

## ① リポジトリを作る

https://github.com/new を開きます。

### 入力内容

| 項目 | 入れるもの |
|---|---|
| Owner | `Atsushi2002`（そのまま） |
| **Repository name** | `lecture-audio-ai` |
| Description | `講義音声から文字起こしと要約を作るWebアプリ（研修課題5）` |
| Choose visibility | **Public**（そのまま） |
| Add README | **Off**（そのまま） |
| Add .gitignore | **No .gitignore**（そのまま） |
| Add license | **No license**（そのまま） |

### なぜこの設定？

- **Repository name**: 半角英数字とハイフンのみ。日本語・スペースは使えません。
  ここで決めた名前が、あとで公開URLの一部になります
  → `https://atsushi2002.github.io/lecture-audio-ai/`
- **Public**: 無料アカウントでGitHub Pagesを使うにはPublicが必要です。
  課題も「公開リポジトリ」が前提。
  **Public = 世界中の誰でも見られる**ので、APIキーは絶対に入れないこと（このアプリには入っていません）
- **Add README を Off にする理由**: すでに `README.md` を用意してあります。
  Onにすると中身の違うREADMEが作られて紛らわしくなります
- **Add .gitignore を No にする理由**: 同じく `.gitignore` を用意済みです

緑の **Create repository** を押します。

---

## ② ファイルをアップロードする

リポジトリを作ると「Quick setup」という画面になります。
コマンドがずらっと並んでいますが、**全部無視してOK**です。

### 手順

1. 画面の中ほどにある **`uploading an existing file`** というリンクをクリック
   （文章の中のリンクです。見つからなければ、URLの末尾に `/upload/main` を足してアクセスしても同じ画面に行けます）
2. Finderで `day5-lecture-audio-ai` フォルダを開く
3. **フォルダの中身をすべて選択**（`Command + A`）してブラウザにドラッグ
4. 画面下までスクロールし、緑の **Commit changes** を押す

### ⚠️ 最重要：どのフォルダを上げるか

```
Wi-Fi PS収集データ/
  └ オフィス会議室(株式会社Ling)/     ← ❌ ここを丸ごと上げてはいけない
      ├ Ras3B01/ Ras3B02/ ...          （会社のセンサーデータ）
      ├ 解析結果_20260803/
      └ day5-lecture-audio-ai/         ← ✅ この中身だけ
```

Publicリポジトリなので、間違えると**会社のデータが全世界に公開されます**。
必ず `day5-lecture-audio-ai` を**開いた状態**で、その中のファイルをドラッグしてください。

### 隠しファイルが見えない問題

`.gitignore` はドット（.）で始まるため、Macの Finder では**最初から見えていません**。

**Finderで `Command + Shift + .`（ピリオド）** を押すと、隠しファイルが表示されます。
もう一度押すと元に戻ります。

`.gitignore` が上げられなくても動作には影響しませんが、提出物として含めておくのが望ましいです。

### アップロードされるべきファイル（全13個）

```
index.html
style.css
main.js
README.md
.gitignore
docs/SPEC.md
docs/API_NOTES.md
docs/TESTCASES.md
docs/STATUS.md
docs/PROMPTS.md
docs/GITHUB_GUIDE.md   ← このファイル
tests/smoke.test.mjs
tests/README.md
screenshots/README.md
```

フォルダ（docs, tests, screenshots）はドラッグすれば構造ごと上がります。

### うまくいかないとき

| 症状 | 対処 |
|---|---|
| ドラッグしても反応しない | 「choose your files」をクリックしてファイル選択ダイアログから選ぶ |
| フォルダが上がらない | フォルダを開いて、中のファイルを個別にドラッグする |
| 間違ったファイルを上げた | リポジトリでそのファイルを開き、右上のゴミ箱アイコンから削除 → Commit changes |

## ③ GitHub Pages で公開する

1. リポジトリの上部にある **Settings**（歯車アイコン）をクリック
2. 左のメニューを下にスクロールし、**Pages** をクリック
3. **Build and deployment** の下、**Source** が `Deploy from a branch` になっていることを確認
4. **Branch** の欄で左のプルダウンから **`main`**、右のプルダウンから **`/ (root)`** を選ぶ
5. **Save** を押す

1〜3分待ってからページを再読み込みすると、上のほうに URL が表示されます。

```
https://atsushi2002.github.io/lecture-audio-ai/
```

これが **GitHub Pages URL** です。提出時に必要なのでメモしておいてください。

### 反映されないとき

- **数分待つ**（初回は特に時間がかかります）
- リポジトリの **Actions** タブを見る。緑のチェックが付いていれば公開成功、
  黄色は処理中、赤は失敗
- 404になる → `index.html` がリポジトリの**一番上の階層**にあるか確認。
  `day5-lecture-audio-ai/index.html` のように1段深いと、URLも
  `.../lecture-audio-ai/day5-lecture-audio-ai/` になります

## ④ 動作確認

### 準備：APIキーを取る

1. https://aistudio.google.com/apikey を開く
2. Googleアカウントでログイン、規約に同意
3. **Create API key** をクリック
4. `AIza...` で始まる文字列をコピー（前後に空白を入れないよう注意）

### 準備：テスト用の音声を作る

**30秒程度**の短い音声を用意します。自分の声で講義っぽく喋ればOKです。

⚠️ **iPhoneのボイスメモは `.m4a` 形式で、このアプリでは使えません**
（Gemini APIが対応していない形式のため）。

対応形式は **mp3 / wav / aac / ogg / flac / aiff** です。

**変換が必要な場合は言ってください。** 音声ファイルを
`オフィス会議室(株式会社Ling)` フォルダに置いてもらえれば、こちらで変換します。

> ⚠️ 個人情報や会社の機密が入った音声は使わないでください。
> 「これはテスト用の録音です。今日はエントロピーについて説明します…」程度の内容で十分です。

### 実行

1. スマホで GitHub Pages URL を開く
2. APIキーを貼って「この端末に保存」
3. **「接続テスト」を押す** ← ここが重要
   - `接続OK` → キーは正常。次へ
   - 失敗 → エラー詳細を開いて全文をコピー。この時点で音声の問題ではないと分かります
4. 講義名を入れて、音声ファイルを選択
5. 「文字起こし＆要約を実行」

### エラーが出たら

慌てず、**「詳細」を開いて「詳細をコピー」** を押してください。
そのテキストと `docs/STATUS.md` をAIに貼れば、原因を特定できます。

よくあるエラーの意味は `docs/API_NOTES.md` の「4. エラーの読み方」にあります。

## ⑤ スクリーンショットを撮る

合格判定に必要なのは最低5枚です。

| ファイル名 | 撮るもの |
|---|---|
| `01_top_mobile.png` | スマホのトップ画面 |
| `04_transcript.png` | 文字起こしが表示されている画面 |
| `05_summary.png` | 要約と要点が表示されている画面 |
| `06_copy_toast.png` | 「コピーしました」が出ている画面 |
| `08_grep_no_key.png` | リポジトリにAPIキーが無いことの証拠 |

`08` は、GitHubのリポジトリ画面上部の検索窓で `AIza` と検索し、
**「0 results」と出ている画面**を撮ればOKです（ターミナル不要）。

### ⚠️ 撮る前の確認

- **APIキーが写っていないこと**（「表示」を押さずマスクのまま撮る）
- 通知バナー、他のタブ名、個人情報が写っていないこと

### アップロード

1. リポジトリの `screenshots` フォルダを開く
2. **Add file → Upload files**
3. スクショをドラッグ → **Commit changes**

## ⑥ 提出

先に `docs/STATUS.md` の以下の欄を埋めます。

- リポジトリURL
- GitHub Pages URL
- 「詰まった点」（実際に詰まったことを1〜3行）

GitHub上でファイルを直接編集できます：ファイルを開く → 鉛筆アイコン → 編集 → Commit changes

そのうえで、指定チャンネルに提出します。

```
【研修課題5 提出】
氏名：
GitHubリポジトリURL：https://github.com/Atsushi2002/lecture-audio-ai
GitHub Pages URL：https://atsushi2002.github.io/lecture-audio-ai/
最小機能：OK
工夫した点（1〜3行）：
詰まった点と解決（1〜3行）：
```

### 「工夫した点」に書けること（実際にやったこと）

- 実装前に公式ドキュメントを調べ、モデル名や音声の制限を `docs/API_NOTES.md` に根拠URL付きで固定した。AIが古いモデル名（`gemini-1.5-*`）を出す問題を先回りで防いだ
- 文字起こしと要約を別リクエストに分け、さらに「接続テスト」ボタンを付けて、
  詰まったとき「キーの問題か／音声の問題か」を1タップで切り分けられるようにした
- エラー時にレスポンス全文を画面に出し、そのままAIに貼って相談できるようにした

---

## 困ったときの順番

1. まず **接続テスト** を押して、キー側か音声側かを切り分ける
2. エラーの「詳細をコピー」でテキストを取る
3. `docs/STATUS.md` を更新する
4. エラー全文＋公式URL（https://ai.google.dev/gemini-api/docs/audio）を添えてAIに聞く
5. それでもダメならメンターに `docs/STATUS.md` を渡す

**15分詰まったら、自力で粘らずこの手順に切り替えてください。**
これは課題ガイドの「コツ10」そのもので、現場でも有効な型です。
