# PROMPTS.md — AIに投げた重要プロンプトと採用した答え

このアプリを作る過程で効いたプロンプトを、**そのままコピペして再利用できる形** で残します。
「何を聞いたか」より「なぜそう聞いたか」が資産になります。

---

## 1. 調査：最新モデル名と音声の制限を取りに行く

### なぜ

AIは学習データが古く、`gemini-1.5-flash` のような**存在しないモデル名**を平気で出してくる。
実装より先に公式から事実を取り、仕様に固定してしまうのが一番の時短。

### プロンプト

```
Gemini APIで「音声ファイル → 文字起こし」をブラウザから直接叩きたいです。
推測で答えず、下記の公式ドキュメントを実際に読んで、根拠URL付きで答えてください。

- https://ai.google.dev/gemini-api/docs/models
- https://ai.google.dev/gemini-api/docs/audio

知りたいこと：
1. 現在 Stable として一覧に載っているモデル名（文字列そのまま）
2. 公式の音声ガイドのサンプルコードが使っているモデル名
3. 廃止・シャットダウン済みで使ってはいけないモデル名
4. RESTのエンドポイントURLと認証ヘッダの正確な形
5. インライン送信のサイズ上限と、対応している音声MIMEタイプの一覧
6. 上限を超えたときの代替手段

出力は表形式で、各行に根拠URLを付けてください。
```

### 採用した答え

| 項目 | 結論 |
|---|---|
| 既定モデル | `gemini-3.5-flash`（公式Audioガイドのサンプルと同じ） |
| 選択肢 | `gemini-3.6-flash` / `gemini-3.5-flash-lite` / `gemini-3.1-flash-lite` |
| 使わない | `gemini-1.5-*`（一覧に存在しない）、`gemini-2.0-flash`（Shut down） |
| エンドポイント | `POST https://generativelanguage.googleapis.com/v1beta/models/{MODEL}:generateContent` |
| 認証 | ヘッダ `x-goog-api-key: <KEY>`（Bearer でも `?key=` でもない） |
| インライン上限 | リクエスト合計 20MB。超えるなら Files API |
| 対応MIME | wav / mp3 / aiff / aac / ogg / flac（**m4a は無い**） |

根拠: https://ai.google.dev/gemini-api/docs/models , https://ai.google.dev/gemini-api/docs/audio

→ 詳細は `docs/API_NOTES.md`

## 2. 仕様固め：AIに先に質問させる

### なぜ

いきなり「作って」と言うと、AIが勝手に前提を埋めて的外れなものを作る。
**質問させてから答える**ほうが、結果的に早い。

### プロンプト

```
非エンジニアです。講義の録音から「文字起こし・要約3行・要点3〜5個」を作る
スマホ対応Webアプリを作りたいです。

いきなり実装せず、まず仕様を固めたいです。
仕様を確定するために、あなたが判断できない点を質問形式で10個以内で挙げてください。
選択肢がある質問は選択肢も出してください。
私はそれに答えるだけにしたいです。
```

### 採用した答え（＝確定した仕様）

- 音声入力は **ファイル選択のみ**（録音は発展扱い）→ 最短で通す
- 保存機能・共有機能は **やらない**（MVPの範囲を絞る）
- 文字起こしと要約は **2リクエストに分ける** → 切り分けやすさ優先
- APIキーは **localStorage**（サーバーを立てない）
- 対象ブラウザは iOS Safari / Android Chrome

→ `docs/SPEC.md` に反映

## 3. 実装：詰まりにくい順番を固定させる

### なぜ

一気に全部作らせると、失敗したときに原因が特定できない。
公式トラブルシュートも「まずテキストだけで通す」を推奨している。

### プロンプト

```
実装を3段階に分けてください。各段階が終わった時点で
「動いているか確認する方法」も書いてください。

STEP1: テキストだけで generateContent が通ることを確認する最小コード
STEP2: 短い音声（30秒）を inline_data で送って文字起こし
STEP3: 文字起こし結果を渡して要約・要点

条件:
- モデル名は公式Models一覧のものだけを使う
- 認証は x-goog-api-key ヘッダ
- SDKは使わず fetch で直接叩く
- APIキーはコードに書かない（localStorage）
```

### 採用した答え

STEP1 を捨てずに **「接続テスト」ボタンとしてUIに残した**。
これがこのアプリで一番効いた判断で、トラブル時に「キーの問題か／音声の問題か」を1タップで切り分けられる。

## 4. 文字起こしのプロンプト（アプリに組み込んだもの）

### なぜ

素で「文字起こしして」と頼むと、AIが勝手に要約したり「はい、承知しました」と前置きを付ける。
**やってほしくないことを明示**するのが効く。

```
あなたは日本語の講義音声を文字起こしする書記です。
この音声は「{講義名}」という講義の録音です。

次のルールで、音声の発話内容を文字起こししてください。
1. 話された内容を省略せず、全文をそのまま書き起こす。
2. 「えー」「あのー」などのフィラーは削り、読みやすい文にする。
3. 話題が変わるところで改行して段落を分ける。
4. 聞き取れない箇所は [聞き取れず] と書く。
5. 要約や感想、前置き、見出しは書かない。文字起こし本文だけを出力する。
```

**ポイント:** ルール5がないと前置きが混ざる。また `temperature: 0` を指定して創作を防いでいる。

## 5. 要約のプロンプト（アプリに組み込んだもの）

```
あなたは大学生の学習を助けるノート作成アシスタントです。
次の講義の文字起こしを読み、日本語で要約してください。

出力は、余計な説明やコードブロック記号を付けず、次のJSONだけを返してください。
{"summary": "3行程度の要約", "points": ["要点1", "要点2", "要点3"]}

制約:
- summary は3行程度（150〜250字目安）。専門用語はそのまま残す。
- points は3〜5個。各40字以内。試験に出そうな要点を優先する。
- 文字起こしに書かれていないことは書かない（推測しない）。

講義名: {講義名}

--- 文字起こし ここから ---
{文字起こし}
--- 文字起こし ここまで ---
```

**ポイント:** 「JSONだけ返して」と書いても ` ```json ` で囲まれて返ることがあるので、
コード側で **コードフェンス除去 → `{}`の抽出 → 箇条書きフォールバック** の3段構えでパースしている。
プロンプトだけに頼らず、コード側でも受け止めるのが安全。

## 6. 詰まったときに投げるテンプレ（そのまま使える）

```
目的：講義音声ノートAI（Gemini API連携）を作っています。
現状：UIはできました。APIキー入力→保存もできています。接続テスト（テキストのみ）は成功します。
問題：音声ファイルを選んで実行すると400エラーになります。
期待：音声から文字起こしが返ってきて画面に表示されること。

エラー全文：
（アプリの「詳細をコピー」で取得したものを貼る）

該当コード：
（main.js の generateContent 関数を貼る）

公式URL：
https://ai.google.dev/gemini-api/docs/audio

制約：
- APIキーはGitHubに入れない（localStorage）
- 音声は30秒の短いサンプルで検証中
- モデルは gemini-3.5-flash

依頼：
原因候補を3つ出し、それぞれ「確認手順 → 修正案 → 修正パッチ」の順で提案してください。
推測ではなく、公式URLを根拠にしてください。
```

**ポイント:** 「現状」に **成功していること** も書く。
「接続テストは成功する」の一文があるだけで、AIはキー・エンドポイント側の原因候補を除外でき、当てずっぽうが減る。

## 7. 学んだこと（プロンプトの型）

| 型 | 効果 |
|---|---|
| **公式URLを渡して「推測禁止・根拠URL必須」と書く** | ハルシネーション（古いモデル名など）が激減する |
| **実装前に「質問を10個出して」と言う** | 仕様が速く固まる。手戻りが減る |
| **段階を切って「各段階の確認方法も書いて」と言う** | 切り分けポイントが自然にUIに残る（＝接続テストボタン） |
| **「やらないこと」を明示する** | 前置き・勝手な要約・余計な機能が減る |
| **成功していることも一緒に伝える** | 原因の絞り込みが速い |
| **プロンプトだけに頼らずコード側でも受け止める** | JSONがコードフェンスで返っても壊れない |
